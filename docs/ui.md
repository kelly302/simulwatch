# 画面と UI

CLAUDE.md から移した（2026-11-04。文言は変えずにそのまま移した）。CLAUDE.md と同じく**実装と同じコミットで直す**。未実装の決定は docs/decisions.md が優先する（印「→ D-xx」の付いた文）。

## クライアントに渡す JSON

- 画面ごとに分割する。**全データを1ファイルにまとめない**。1ファイル数十KBを目安にする（絞り込み用の全件の索引（ID だけ。作品を付けない枠はタイトルも持つ）と辞書は例外）。
- トップは4ブロックを HTML に入れ（ランキングは期間3種）、JSON は「すべての同時視聴」の操作のあとに読むぶん（新しい順300枠・全件の索引・辞書。site/pages/data/top/）だけを生成する。
- 各一覧は、一覧表示に必要な項目だけを入れる。
- 作品ページと配信者ページの本文は HTML に持たせ、ページごとの JSON は作らない（2026-10-03 決定。下の「Phase 3 の UI・SEO の決定」）。
- **作品一覧は並び順ごとに300件ずつのページ JSON に分ける**（作品は数千件になり、一覧の項目だけでも1ファイルの目安を超えるため）。
  検索は作品名だけの軽い索引を別に作り、検索欄を触ったときに読む（ゲート2で決定）。

## 画面構成

画面は6つ。トップ / 作品一覧 / 配信者一覧 / 作品ページ / 配信者ページ / ランキング（/ranking/。2026-10-21 ユーザー決定。トップの順位表の続き）。
トップに検索窓は置かない。検索と絞り込みは各一覧ページの中に置く。
モバイル前提。出口は YouTube（サムネをクリックで遷移。埋め込み再生はしない）。
スマホ（幅 720px 未満）はトップ・作品・配信者のナビを画面の下のタブにする（2026-10-20。下の「UI の作り直し」）。

トップは3ブロック（2026-10-20 に「よく同時視聴される作品」を足して4ブロック、2026-10-27 の決定 D-01 で「これから始まる枠」を外した）。ランキングは縦の順位表、よく同時視聴される作品は横に流す棚、「すべての同時視聴」はグリッド。並び順とフィルターはブロックごとに独立。

    1. ランキング              枠単位。期間内の再生数順。既定7日（7/30/全期間。7日に枠が無ければ30日、それも無ければ全期間）。
                               縦の順位表に5枠（どの幅でも1列）。「30位まで見る」はランキングのページへ移る（その場では開かない）
    2. よく同時視聴される作品  作品一覧の既定の並び（観た配信者の多い順）の先頭12作品。棚。作品の画像・作品名・観た配信者数・枠数
    3. すべての同時視聴        completed のみ。既定は started_at 降順。グリッド（見出しは 2026-10-21 に「すべての同時視聴」から改めた。ユーザー決定）

行の表示項目は、並び替えのキーと開く判断に要る値だけに絞る。

    作品ページの配信者行   アイコン / 名前 / 所属 / メン限バッジ / views_max / 最終視聴日
    配信者ページの作品行   作品画像 / 作品名 / 最終視聴日 / 枠数（作品画像は 2026-10-20 に足した。画像の無い作品は種別形式の桃色の札）
    作品一覧の作品行     作品画像 / 作品名 / 観た配信者数 / 最終視聴日
    展開行               日付 / 再生数 / メン限バッジ / サムネ。日付の昇順

### Phase 3 の UI・SEO の決定（2026-10-02〜03。2026-10-19 に実装した。下の「Phase 3 の実装」）

UI を作る別の会話で、モックアップを見ながら決めた（2026-10-03 に SEO のレビューを受け、推奨をすべて採用）。2026-10-09 の整理でその会話の記録から写し、ユーザーが確認した。

画面:

- 作品種別は「アニメ / 特撮 / 実写」（「海外」はやめた）。種類と映画は1軸にまとめない
- 作品ページ: 所属の内訳は出さない。「同じシリーズの作品」（series_id。放送順）を置く。パンくず（トップ › 作品 › 種類 › 作品名）
- 配信者ページ: 全行を HTML に出す（「さらに表示」なし）。読みがなは Annict にしかないので、漢字の作品名は名前順で末尾に寄る。
  Annict のシリーズは区切りが一定でない（Fate の UBW の1期と2期が別のシリーズ）ので、シリーズ名で並べる案は使わない
- 1枠に複数作品が付く枠は作品名を並べる（3行で切る）。行・カードに「種別形式 · 時期（または話数）」。サムネには何も重ねない
- 所属の表記: 一覧の行は「にじさんじ EN」（日本は区分を書かない）。枠カードは日本以外の区分だけ名前の後ろに小さく。EN・KR・ID の配信者は英語の名前を併記
- 一覧: 作品一覧の種類のタブ・配信者一覧の所属のタブはリンク（/works/anime/、/streamers/nijisanji/ のような静的な一覧ページ。画面の使い回し）。
  作品一覧の既定の並びはページ送りのリンク（300件ずつ）。配信者一覧は全員を1ページに、区分はページの中のチェック
- h1 は「同時視聴された作品」「同時視聴した配信者」。トップにも h1（「にじさんじ・ホロライブ・ぶいすぽっ！の同時視聴まとめ」。2026-10-20 ユーザー決定。
  title は「VTuber 同時視聴まとめ | にじさんじ・ホロライブ・ぶいすぽっ！のアニメ・映画同時視聴」。2026-10-23 ユーザー決定。トップだけサイトの名前を前に。ほかのページは「… | サイトの名前」）。トップの h1 の下の説明文は置かない（2026-10-20）。Web フォントはやめて端末のフォント

SEO・実装:

- **本文はビルド時の HTML、JSON は操作のあとだけ**。トップは HTML にランキング3期間・よく同時視聴される作品・新しい順24枠 → 「さらに表示」で新しい順300枠の JSON →
  絞り込み・並べ替え・300枠より先で全件の索引（ID だけ）と辞書。件数は索引を読んだあとに出す
- URL: 作品は外部DB の ID（annict > anilist > wikidata）を**一度決めたら変えない公開キーの列**にする（works.id は名寄せで消して作り直されるので使えない）。
  行をまとめて変わったら Cloudflare の _redirects で 301（固定の転送は2,000行まで。末尾スラッシュの無い形も書くので1転送2行で、1,000転送まで。超えると astro.config.mjs がビルドを失敗させる）。配信者は channel_id。絞り込み・並び順は URL に出さない。末尾スラッシュ・自己参照の canonical
- インデックス: 配信者1人の作品ページも noindex にしない（中身を厚くする）。枠0のページは作らず 404。JSON は X-Robots-Tag: noindex（robots.txt で塞がない）。
  sitemap の lastmod はデータが変わった日
- title の例「コマンドー（1985年の映画）の同時視聴 配信者10人・15枠 | VTuber 同時視聴まとめ」（「| 」のあとはサイトの名前。config/site.yaml の site_name）。構造化データは BreadcrumbList・WebSite・作品の Movie/TVSeries と sameAs（Wikidata・Annict など）。VideoObject は使わない
- og:image はビルドで作る自作の画像（作品ページ・配信者ページごと。YouTube・AniList の画像を使わない）。ほかのページはサイト共通の1枚
- 英語の名前: にじさんじは名簿で読んでいる API の応答の enName（追加の取得なし）。ホロライブは /en/talents?gp=<group>（今の parseHololiveGroup のまま読める。
  取得が17回増える。[Affiliate]・[Alum] を外す）。Streamer に列 name_en を足す（下の決定 C）
- Cloudflare Pages の無料プランは1サイト20,000ファイルまで（→ D-02 で Workers に変更予定・未実装。Workers の静的アセットも1版20,000ファイル）。**作品ページごとの JSON は作らず、HTML に持たせる**
- 公開の手順の下書きと未決事項（Pages か Workers か・独自ドメイン・生レスポンスの保存期間など）は docs/deploy.md（→ D-02 で決まった・未実装）
- 公開後: Search Console で、配信者1人の作品ページとそれ以外のインデックス状況を分けて見る

### Phase 3 の初めの決定（2026-10-19。A〜D）

UI の会話が出した4つの推奨を、Phase 3 の会話でユーザーが確かめて決めた。

- A ~~予定時刻から6時間を過ぎても upcoming の枠は「これから始まる枠」に出さない~~（2026-10-27 の決定 D-01 で予定枠・配信中の枠をサイトに出さなくなり、意味を失った。
  config/site.yaml の `publish_upcoming` を true にして予定枠を出すときだけ `upcoming_stale_hours` が効く）
- B **シリーズが分かれた作品群（名探偵コナン・ポケモンの劇場版と TV 版）は Phase 3 では寄せない**。「同じシリーズの作品」は series_id のまま
- C 列の名前は `works.public_key`・`streamers.name_en`。**URL は `/works/annict-1234/`・`/works/anilist-5678/`・`/works/wikidata-Q123/`、配信者は `/streamers/<channel_id>/`**。
  works の行は名寄せで作り直されるので、一度出した公開キーは別の表に覚えておき、行がまとまって変わったときの 301 をそこから作る
- D Pages か Workers か・独自ドメイン・コミットの作者のメールアドレスは、公開の前（Phase 4 の最初のアップロードの前）に決める（docs/deploy.md の 6-1・6-2・6-6）（→ D-02 で決まった・未実装）。
  Phase 3 のビルドは仮のサイトの URL を設定に置いて進める

### Phase 3 の実装（2026-10-19）

    npm run cli -- site:data    DB → data/site/site-data.json（出す枠・作品・配信者・集計値・公開キー・lastmod・301）。src/publish/
    npm run site:build          Astro の SSG → dist/（HTML・JSON・og:image・sitemap・robots・_headers・_redirects）。site/

- **出す枠は publishState（src/resolve/route.ts）の work・frame だけ**。書き出しのたびに集計値を作り直す（集計は終わった枠だけ。再生数は公開枠だけ）
- **作品の公開キーの表（work_public_keys）と、ページの中身の指紋（site_pages。lastmod）は site:data が DB に書く**（src/publish/keys.ts・snapshot.ts）
- ビルドとブラウザは同じ関数でカードと行を作る（site/lib/views.ts）。ブラウザに渡す JSON の形は site/lib/encode.ts、表示の決まり（種別形式・時期・話数・再生数・並べ替え）は src/shared/site.ts
- 設定は config/site.yaml（仮のサイトの URL・予定枠を出すかの切り替え（`publish_upcoming`。D-01 で false）と出すときの6時間・ランキングの枠数・ページの件数）
- og:image は satori と resvg で描く（フォントは Noto Sans JP。1枚約90ms）。中身が同じ画像は data/site/og-cache/ のものを使う（無いと全部で約3分）
- 実装のときに決めたこと（モックアップに無かったところ。ユーザーの確認待ち）:
  ランキングは作品の付いた公開枠だけで期間ごとにトップは5枠・ランキングのページは30枠（config/site.yaml の top.ranking_top・ranking_page。最初は8枠で、2026-10-20 に「続きを見る」で30位までにし、2026-10-21 ユーザー決定で今の形）／配信者ページの末尾に「作品ページの無い枠」（外部DBに無い作品・作品を特定できない枠）を並べる／
  映画かどうか・制作国が分からない作品は、絞り込みの「映画」「映画以外」「日本」「海外」のどれにも入れない／広告の枠は広告の配信を決めるまで出さない／
  このサイトについて（/about/）・プライバシーポリシー（/privacy/）は下書き（運営者・連絡先・広告の節は公開の前に決める）
- **メン限の印（is_members_only）があっても、終わった枠で再生数が取れていれば公開の枠として扱う**（メン限のバッジを出さず再生数を出す。ランキング・再生数順にも入る。
  2026-10-22 ユーザー決定。印は題名の語（メン限など）でも立つが、メン限の動画は再生数が取れない。10-21 の DB で、メン限の再生リストで見つかった 1,513枠は再生数が取れた枠が0、
  再生数が取れた印つきの11枠はすべて公開の一覧で見つかった枠で「メン限特別公開！」など公開に切り替えた枠だった。src/publish/snapshot.ts）
- site:data は最初に前回の site-data.json を消す（書き出しに失敗したら、ビルドが古いデータで成功してアップロードされないように、ファイル無しでビルドを失敗させる。
  ジョブの終了コードは 0 のまま）。公開キーの表の外部DBの ID は、今の作品に付けたキーでは今の作品の ID に置き換える（足し続けると、作品が分かれ直したあと無関係な作品へ転送する）。
  _redirects は末尾スラッシュの無い形も書く（2026-10-22。Fable のレビュー）
- 作品が0の種類のタブ（/works/tokusatsu/ など）は作らない（固定のページなので、ビルドの終わりに astro.config.mjs が消す。タブのリンクと sitemap からは外してある。2026-10-26）。
  ランキングの枠数は config/site.yaml の top.ranking_top（トップ。5）と top.ranking_page（ランキングのページ。30）
- ブラウザが操作のあとに読む JSON のページは site/pages/data/。**`.gitignore` は直下の `/data/` だけを無視する**（`data/` と書くと site/pages/data/ まで無視され、a41fc60 に入っていなかった。2026-10-20 に直した）

### UI の作り直し（2026-10-20）

ユーザーの不満は「色・質感が地味」と「文字と余白の釣り合い」。awesome-design-md の DESIGN.md（Spotify・The Verge・WIRED・Notion・Linear）と、
Holodex・Letterboxd・Filmarks・Netflix の組み立てを参考に、実データで4案（A 棚・B 誌面・C 作品棚・D 一覧表）の試作を並べ、
ユーザーが **見た目は B「誌面」、構成は A「棚」** を選んだ。

- 見た目（最初の作り直し。下の「雰囲気をポップに」で置き換えた）: 白い紙に黒の太い罫（3px）と、極太の見出し・数字、紫 #5200FF とミント #3CFFD0
- 構成: トップのよく同時視聴される作品は横に流す棚（マウスの端末だけ見出しの右に矢印。site/scripts/rail.ts・components/RailButtons.astro）。
  スマホはナビを画面の下のタブに。作品ページは作品画像を中央に大きく出す（画像の無い作品は作品名だけ）。開いた行の枠は横に流す。
  同じシリーズの作品は作品画像の棚。配信者ページの「作品ページの無い枠」は2列（PC は4列）
- 画像の無い作品（実写・特撮・海外の作品）の作品カードは、作品名と種別形式・時期を組んだ文字のポスター（桃色の地に白字。テーマに関係なく同じ）
- 変えていないこと: 5画面（2026-10-21 にランキングのページを足して今は6画面）と URL・JSON の分け方・作品一覧・配信者一覧・作品ページ・配信者ページの h1・パンくず・canonical・構造化データ・title の形・
  サムネに何も重ねない・メン限の再生数は「—」・タッチの的 44px 以上（カードの作品名の文中リンクを除く。前と同じ）・
  文字のコントラスト 4.5:1 以上（ボタン・入力欄の枠線は 3:1 以上）

作り直したあとの見直し（2026-10-20。ユーザーの感想と、Fable（claude-fable-5-1）のレビュー）:

- 件数の説明（「○人・○作品・○枠を載せています」）は、トップと「このサイトについて」の両方から外した。トップの h1 の下の説明文も消した。
  件数は meta description と サイト共通の og:image には残している
- トップの h1 を「にじさんじ・ホロライブ・ぶいすぽっ！の同時視聴まとめ」に（Fable の候補から。事務所名は検索語）。事務所名の途中では折り返さない
- **サイトの名前は「VTuber 同時視聴まとめ」にする**（2026-10-22 ユーザー決定。トップの title で「まとめ」が2回出ていたのを受けて名前を考え直した。
  名前は config/site.yaml の site_name だけに書き、title・ヘッダー・フッター・og:image はそこから作る（og:image のキャッシュの鍵にも名前を入れている）。2026-10-26 に site_name を書き換えた）
- ランキングは**縦の順位表**（2026-10-21 ユーザー決定。2段の棚は順位が読みにくかった。試作の3案（縦の順位表・上位を大きく・1段の棚と大きな数字）から）。
  行は左に大きな順位、サムネイル、作品名・配信者・再生数。**どの幅でも1列で上から**（列をまたがせない。2列にすると順位が列をまたいで飛ぶ。2026-10-21 ユーザーの指摘）。
  トップは5位まで（8位までだと1画面がほぼ埋まる。ユーザーの指摘。config/site.yaml の top.ranking_top。ランキングのページは top.ranking_page の30位まで）。
  幅 720px 以上は行を横に広く使う（サムネイル・作品名と種別・配信者・日付と再生数を横に並べる）。7日に枠が無いときだけ30日（それも無ければ全期間）を最初に出す。
  **続きはランキングのページ**（/ranking/。2026-10-21 ユーザー決定。その場で30位まで開くと、PC で順位が列をまたいで飛んだ）。3期間とも30位まで HTML に入れ、期間はトップと同じ切り替え。
  トップで選んでいた期間で開く（sessionStorage で引き継ぐ。URL には出さない）。h1「同時視聴ランキング」・パンくず トップ › ランキング・sitemap に入れる・下のタブには入れない。
  ランキングのページも1列で 1→30。部品は site/lib/ranking.ts・site/scripts/rank.ts（トップと共通）
- 「すべての同時視聴」の絞り込みは、3案（軸のボタン・選択肢を段に並べる・1本の帯）を試作で並べ、ユーザーが **軸のボタン** を選んだ。
  「並び」と「条件」の2段。条件は軸（配信日・所属・作品の種類・映画かどうか・制作国・作品の放送年）のボタンを横に並べ、
  押すとその軸の選択肢が**条件の段のすぐ下に開く**（重なるシートにしない。2026-10-20 ユーザーの指摘）。選択肢は丸い札で、選ぶと桃色の地に白字とチェックの印。
  **選んだらすぐ絞り込む**（2026-10-21。「○枠を表示」のボタンはやめ、開いた欄には「クリア」と閉じるだけを置く）。
  **所属は事務所の札を横に並べ、札そのものにチェック**（2026-10-21 ユーザー決定。試作の5案（事務所と区分の2行・区分はあとから出る・ボタンを2つに分ける・選択のメニュー1つ・件数つきの一覧）から
  事務所を並べたいとのことで、事務所ごとの選択→複数を選びにくい→札の下にチェックの一覧が開く形（試作の P1）→札そのものにチェック、と決めた。
  事務所を札にして区分を縦線でつないだ形・事務所ごとの段の形・札が折り返す形・札を横に流す形・事務所のチェックの下に区分のチェックを縦に並べる形はやめた）。

## ソートとフィルター

ソートは「キー」＋「共通の逆順トグル」。昇順・降順を別の選択肢にしない。

    作品ページ      既定 views_max。選択 latest_event_at
    配信者ページ    既定 名前順（読みがな、無ければ作品名。2026-10-03 決定）。選択 latest_event_at / views_max
    作品一覧        既定 配信者数。選択 views_max / latest_event_at
    配信者一覧      既定 latest_event_at 降順。選択 枠数 / 作品数

作品一覧の既定（配信者数）で同じ配信者数の作品は、latest_event_at の降順で並べる
（作品の約3分の2は配信者数1で同順位になるため。ゲート2で決定）。

views_total / events_count / first_event_at は表示専用。ソートキーにしない。
views_* のソートは実施済み枠のみを対象にする。

**views_max が空（NULL）の行の並び**（メン限枠の再生数は API 仕様上取得できないため）:

- views_max でのソート中、views_max が NULL の行は**逆順トグルに関係なく末尾**に置き、その中では latest_event_at の降順で並べる
- NULL を「0」として扱わない（0回再生の公開枠と区別する）
- トップのランキングは公開枠のみで決まる（意図どおり）

「すべての同時視聴」のフィルターは5軸（2026-10-03 に期間を外して4軸にし、2026-10-20 にユーザーの希望で配信日を戻した）。
