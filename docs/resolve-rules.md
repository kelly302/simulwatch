# 名寄せ（extract / resolve）の細かい決まり

CLAUDE.md から分けた（2026-10-09）。**今の決まりを書く場所**で、経緯の記録ではない。
src/resolve/ と config/extract.yaml を変えるときは先に読み、**実装と同じコミットで直す**（CLAUDE.md と同じ扱い）。

- 方針と骨子: CLAUDE.md の「名寄せ（extract / resolve）」
- 同定の型と AI の判定: CLAUDE.md の「同定の型と AI の判定」
- 検証と、AI の判定の回ごとの記録: docs/ai-runs.md

**方針: 取りこぼしより誤同定のほうが害が大きい。** ルールは `config/extract.yaml`。変えたら `resolve --all` で再処理する。

## extract（タイトルから区間を切り出す。照会しない純粋関数）

- 括弧（【】〖〗など）・ノイズ語（同時視聴・メン限・初見 など）・「｜」「／」・装飾記号を区切りにして、タイトルを**区間**に分ける
- 半角の「/」と単独の空白では区切らない（Fate/Apocrypha、「ジョジョの奇妙な冒険 第3部 …」の先頭だけを切り出して誤同定しないため）
- 配信者名・所属を含む括弧は捨てる。『』「」〈〉の中身は優先の区間にする
- 区間の端の語（を見る・続き・アニメ など、`trim_words`）だけを外す。端にしか効かないので作品名の中の語は壊さない
- 話数は「第7話～第12話」「16~20話」「Ep17」「第壱話」を読む。「全八話」（全話数）と「#10」（配信の回数）は話数にしない
- `not_a_work` の語（Direct・競馬・大会・初配信・ボイス など）があれば照会せず「作品ではない」にする。作品名を巻き込む語は入れない（「ダービー」は「ウマ娘 プリティーダービー」を巻き込む）。
  語はハッシュタグの中も見る（大会名・イベント名はハッシュタグに書かれることが多い。「#日本ダービー」。外すと57枠が「作品ではない」から漏れた）。
  作品名だと明示された括弧（「映画「さがす」」「アニメ『かくしごと』」、`not_a_work_quote_override`）があれば、
  その括弧の中身だけを照会し、作品に当たれば同定する
- 作品名の括弧の中の「#」はハッシュタグではなく装飾として消す（「機動戦士ガンダム #水星の魔女」）
- **区間の直後に続く作品名の括弧は副題**として、区間と副題をつなげた作品名も試す（「ドラゴンボール超「ブロリー」」→「ドラゴンボール超 ブロリー」）。
  区間だけの一致（シリーズ名でテレビシリーズに当たる）は採用しない。括弧が続けて並べば同じ区間の副題とみなす。
  テレビの回の題名（「名探偵コナン「揺れる警視庁」」）も同じ形なので保留になる（取りこぼしとして受け入れた）
- 企画名・番組名（`program_names`。「おはすず日曜日拡大版」）は作品名の候補にしない。ほかに作品名が無ければ「同時視聴だが作品を特定できない」にする
- 話数とハッシュタグは、タイトルの中の位置（区間との前後）も残す（話数をどの作品に付けるかに使う）
- 異体字セレクタ（「┊︎」の後ろの U+FE0E）とゼロ幅の文字は消す。話が付かない丸数字（「レイアース⑪」）は番号として区間から外す（「⑰話」は話数）。
  番号の付いた区間は映画には同定しない（「パイカリ③」は何作目か分からない）
- 区間が一致しなかったときの言い換え（小区間）: 「〜と見る」の相手を外した形（「医療従事者と見るアンナチュラル」→「アンナチュラル」）、
  読み仮名の括弧の両側（「刃牙（バキ）」「LOKI -ロキ-」。括弧の後ろに語が続く「スプライス(SPLICE)を一緒に見よう」も）、
  部・1期の表記を外した形（部の特定は照合側で確かめる）、前後の語を外す前の形（「その着せ替え人形は恋をする」の「をする」を外しすぎないため）、
  和英を空白で並べた形の両側（「ベイマックス Big Hero 6」。日本語が先なら英字の側が5文字以上で期の表記・OAD などでないとき、
  英字が先なら日本語の側がカタカナだけのとき。「BLEACH 千年血戦篇」「進撃の巨人 OAD」「きさらぎ駅 Re:」を分けない）、
  前置きを外した形（「新海誠監督作品 君の名は。」「劇場版モノノ怪 唐傘」）、
  先頭の短い語を外した形（「大人なカートゥーン ハズビンホテルへようこそ」。後ろが照合キーで6文字以上で、両側とも日本語のときだけ。「I.presage flower」を分けない）、
  タイトルに「見る・みる」などがあるときの先頭の「〇〇と」を外した形（「下僕と83歳のやさしいスパイ（字幕版）みる」）
- 前の語を外したあとに残る「の」も外す（「実写のワンピ見る」→「ワンピ」）。“ ” は括弧にしない（作品名の中の記号。「IT/イット “それ”が見えたら、終わり。」）
- 照合キーはひらがなをカタカナにそろえ（`fold_kana`）、「篇」を「編」にそろえ（「千年血戦編」）、BOM・ゼロ幅の文字・絵文字を落とす（Wikidata のラベルに BOM が混じる）。
  ただし Annict・AniList の検索そのものはひらがなとカタカナを区別するので、「ゆるきゃんΔ」では劇場版が候補に出てこない（残る課題）
- 区間の直後の「!」「?」は、Wikipedia の記事名で試す別の形として残す（「カラオケ行こ!」。照合キーでは落とす）
- 概要欄は、その枠を指す語を含む行の括弧の中身に加えて、**読点で2つ以上並べて末尾が「を見ます」などの行を作品名の列挙として切り出す**
  （「キミとアイドルプリキュア♪、仮面ライダーガヴ、ナンバーワン戦隊ゴジュウジャーを見ます✨」）。末尾の「♪」は作品名の一部として残す。
  **列挙はタイトルに作品名の区間が無い枠だけ**で使う（「新機動戦記ガンダムW、EndlessWaltzを見ます」を2作品にしない）。
  放送日から番組を推定することはしない

## resolve（区間を外部DBに照会して作品を決める）

- 枠ごとの候補は「段」に分ける: 括弧（『』「」など）の中身 → 括弧の外の区間 → 小区間 → 概要欄 → ハッシュタグ。
  **前の段で作品が決まれば、後の段は照会も採用もしない**（括弧で決まった枠の「王覇山軍」「ぺこ」のような決まり文句を照会しない・採用しない）。
  照会は段ごとに全枠まとめて行い、全文検索は最初の2段だけで使う。
  ハッシュタグは配信者名・企画名・イベント名も入るので、**ほかに候補がないときだけ**使う（配信者名・所属のタグは除く）
- 1つの区間の照会の順: Annict → AniList → 日本語版 Wikipedia の記事名 → Wikipedia の全文検索 → Wikidata のラベル。前で決まらなかったときだけ次へ
- Annict・AniList は区間そのままで照会し、一致しなかった区間だけ表記ゆれ用の検索語（先頭の語・先頭4文字・先頭3文字・「劇場版・映画」の前置きを外した語）を足して照会し直す
  （Annict は部分一致なので「進撃の巨人 Season3」はそのままでは0件、「進撃の巨人」なら全シーズンが出る。
  先頭3文字は「ウマ娘プリティーダービー」のように作品名の途中の空白を詰めて書いたとき用）
- **区間の照合キーが作品名（原題・英題・ローマ字・別名）と完全一致したときだけ採用する**。部分一致は採用しない
  （「鋼の錬金術師FA」を「鋼の錬金術師」(2003) にしない）。照合キーは記号・空白を落とし、期・シーズンの表記をそろえたもの
- 同名の作品が複数あれば、タイトルの「劇場版・映画」の有無で映画かテレビかを選ぶ。それでも決まらなければ ambiguous
- Wikipedia は、Wikidata の P31 が作品クラス（映画・テレビ番組シリーズ・テレビアニメ など、`work_classes`）の記事だけを採用する。
  漫画・小説・フランチャイズ・曖昧さ回避・記事の節へのリダイレクトは採用しない。
  区間の記事が作品でなければ「区間 (映画)」などの記事を試す（「国宝」→「国宝 (映画)」）
- 話数は、映画でない作品に、**タイトルの中で話数の直前（無ければ直後）にある区間がその作品の区間のときだけ**紐付ける
  （「【アイカツ！同時視聴会】オンパレード同時視聴【27話＆1話】」の話数の直前は「オンパレード」なので、アイカツ！に話数を付けない）。
  括弧の中身で決まった作品は括弧の中身どうしだけで見る。作品の話数を超える番号（期をまたぐ通し番号）は付けない。
  Annict の作品は Annict の話の表記（number_text）を使う
- Annict で同定した作品には、MyAnimeList の ID で AniList を引いて AniList の ID と画像URLを付ける
- **Wikidata で引いたアニメは、アニメのDBの行にまとめる**（2026-10-02。src/resolve/link.ts。名寄せの最後と ai:apply のあと）。Wikipedia の記事名のリダイレクト
  （「グレンラガン」→「天元突破グレンラガン」）やラベルで当たると Wikidata の行ができ、同じ作品の Annict の行と2行に分かれていた（UI を作る会話で見つかった）。
  Wikidata の項目の MyAnimeList の ID（P4086）・AniList の ID（P8729）がそれぞれ1つ以下なら、同じ ID の行にまとめる・無ければ Annict を作品名で検索して
  MyAnimeList の ID が同じ作品が1つだけならその Annict の作品にする・それも無ければ ID だけ付ける。ID を複数持つ項目（期をまとめた項目）はまとめない。
  ID の無いアニメーションの項目（海外のアニメ）は、照合キーが同じ作品名・映画かシリーズか（tv・web・ova はシリーズ）が同じ・公開年の差が1年以内の
  アニメのDBの行が1つだけならまとめる（「ナイトメアー・ビフォア・クリスマス」は Wikidata が1993年、Annict が日本公開の1994年）。
  初回（2026-10-02 の DB）: 同じ ID の行にまとめた16・Annict の作品にした9・作品名でまとめた3。残る Wikidata のアニメは6件（期をまとめた水星の魔女・ガンダム00と、Annict に無い海外のアニメ）
- MyAnimeList の ID で行をまとめるのは、照会先をまたぐとき（Annict の作品と AniList の作品、Wikidata の項目とアニメのDBの作品）だけ。
  **同じ MyAnimeList の ID を持つ別作品がある**（Annict の「劇場総集編ぼっち・ざ・ろっく！ Re:」と「Re:Re:」）ので、
  その ID を持つ作品が複数あるときはまとめず、画像も付けない。Annict・AniList・Wikidata の ID がどちらにも付いていて違う行は決してまとめない
- どの枠にも付いていない作品（ルールの変更で付け替わったもの）は消す（外部DBから作り直せる派生データ）
- 照会エラー（一時的なサーバーエラーが続いたもの）は `error` として残し、次の `resolve` で再試行する

## 誤同定を防ぐ足切り（ゲート2の初回の実データで見つかった誤同定から入れたもの）

- **アニメのDBの候補は、種別と放送年があるものだけ**。Annict の OTHER・AniList の MUSIC など種別の無い作品と、
  放送年の無い作品（未公開の企画）には同定しない（ゲームのミラー配信「原神」が Annict の未公開企画「原神」に当たっていた）
- **AniList の別名（synonyms）では照合しない**。原題・ローマ字・英題だけ（別名に「SP」「GGO」のような略称が入っている）
- **英数字だけの4文字以下の区間はアニメのDBで同定しない**（「Fate」→ AniList の「運命」、「REC」→ 同名のアニメ など）
- **小区間を「/」で分けるのは和英併記のときだけ**（片側が英字だけ、もう片側が日本語。「Fate/Zero」は分けない）
- **括弧の外の区間で別々の作品が当たったら決めない**（ambiguous）。長さや位置では選ばない
  （「コードギアス反逆のルルーシュR２同時試聴：CODE GEASS Lelouch of the Rebellion」で英題の区間が1期に当たった）
- **同じタイトルに期・続編を示す区間（二期・The Final Season・Season 2 など、`season_qualifiers`）が残っていたら、シリーズ名だけの一致は採用しない**
  （「進撃の巨人同時視聴！The Final Season ep84から」が Season 1 に当たっていた）
- **話数が作品の話数を超えていたら採用しない**（別の期・通し番号）
- **タイトルに「映画・劇場版」があるのにテレビ作品に当たったら採用しない**（映画『ベルサイユのばら』が1979年のテレビ版に当たっていた）
- **小区間は分け方で扱いを変える**。「＆」「×」「+」で分けたものは複数作品になりうる（スーパーヒーロータイムの2本立て）。
  「！」や和英併記で分けたものは同じ作品の言い換えなので、最初に当たった1つだけを採用する（「アルマゲドン / Armageddon」の英題が別の韓国アニメに当たっていた）
- **角括弧 [ ] はタグの括弧として扱わない**（「Fate/stay night [Unlimited Blade Works]」の [ ] を切り離して2006年版に当たっていた）
- **配信者タグの括弧は、作品名の括弧（『』「」）より先に取り除く**（【にじさんじ 4th Anniversary「FANTASIA」】の「FANTASIA」を候補にしない）
- **作品名の括弧の中の全角スラッシュでは区切らない**（「シビル・ウォー／キャプテン・アメリカ」「REC／レック」）
- **照合キーで「+」を落とさない**（「ズートピア」と「ズートピア+」は別作品）
- **アニメのDBで当たった区間も Wikipedia で照合し、同名のアニメ以外の作品（実写映画など）があって、公開年が1年以上違うか種別（テレビ/映画）が違えば決めない**。
  「古い同名アニメがあり、本命は実写映画」という構造の誤同定を防ぐ（「シャザム！」が1990年のテレビ作品に、「アラジン」がアニメ映画に当たる型）。
  記事名（区間・「(映画)」など）に加えて、**全文検索で見つかる「X (2019年の映画)」のような記事も見る**（ゲート2で追加。初回は区間ごとに検索が1回増える）。
  ただし話数付きの枠なら、アニメのシリーズを選ぶ（「ゴールデンカムイ 8話から」）
- **放送期（2025-summer など）の開始より1か月以上前の枠には同定しない**（2025年5月の『カラオケ行こ！』は2025年夏のアニメではなく実写映画）
- **タイトルに「実写」があればアニメのDBの作品には同定しない。「舞台」があればどの作品にも同定しない**（外部DBに舞台版が無い）
- **括弧の外の区間・言い換えの小区間で、短い区間（照合キー4文字以下）だけが当たり、同じ段にもっと長い区間があれば採用しない**
  （「劇場版のZガンダム…3作目！！！ラスト！」の「ラスト」が同名の映画に当たっていた）
- **リメイク**: 「X」で当たっても、「X (2020年版)」のような年付きの同名作品があれば決めない。区間の末尾に年があれば（「ダイの大冒険(2020)」）その年の作品を選ぶ
  （ダイの大冒険の2020年版を観た1〜45話の枠が1991年版に当たっていた）
- **枠の年より後に公開された作品には同定しない**（リメイク・別シーズンの取り違えを拾う）
- **Wikipedia の「(映画)」以外の接尾辞の記事（「(テレビドラマ)」など）や、全文検索の限定の括弧付き記事（「(東映)」「(2002年の映画)」）は、
  同名の曖昧さ回避ページがあれば決めない**（「スパイダーマン」が1978年の東映版に当たっていた）。
  「X (映画)」は Wikipedia の慣例で同名の映画が1本のときの記事名なので、曖昧さ回避ページがあっても採用する
- Wikipedia・Wikidata への照会は POST で送る（記事名50件をまとめると GET の URL が長すぎて 414 になる）。
  1回の照会が落ちても他は続け、落ちた記事名を使う区間だけ `error` にする。検索の混雑エラーは待って再試行する
- AniList のキャッシュは生の応答で持ち、候補への変換は読み出すときに行う（変換のルールを変えても照会し直さない）
- **Wikidata の wbgetentities は応答が約12MB を超えると後ろの項目を黙って切り捨てる**（warnings に truncated。国の項目やキャストの多い映画の項目が50件並ぶと超える）。
  返ってこなかった項目は分けて取り直す（1件でも返ってこなければ failedQids。2026-10-02）。それまでの名寄せへの影響は、記事の QID 16,479 件のうち
  項目のキャッシュが無いものが7件で、作品の項目は0件（ラベル検索の候補はすべての項目を引かないので、この方法では測れない）

## 分割クール（2026-10-21 ユーザー決定。src/resolve/splitcour.ts・config/extract.yaml の `split_cour`）

Annict は1つの放送を前半と後半の作品に分ける（Fate/Zero 1stシーズン・2ndシーズン、水星の魔女 Season1・Season2）。作品ページが割れて、通しで観た配信者が
2つのページに分かれていた（兎田ぺこらの Fate/Zero は 12〜19話の枠が 1stシーズンだけに付いていた）。**分割クールは前半の作品の行に1作品としてまとめる。本当の2期は分けたまま。**

- 名寄せ（resolve）と AI の判定（ai:apply）は今までどおり前半・後半の作品に付け、最後に（Wikidata のアニメのまとめの次に）まとめる。期の取り違えの規則はそのまま効く
- 見分け方: Annict の同じシリーズのテレビ作品 A・B で、次の3つがそろえば B を A にまとめる
  1. B の最初の話の番号が A の最後の話の番号の次（話の表記（第十四話・#13・MISSION:13）を先に読み、読めなければ number。シンデレラガールズ 2nd SEASON の「第26話」は number が 0）
  2. 放送の間が3期以内（`max_gap_seasons`。MFゴースト 2nd Season（1年後）は本当の2期）
  3. B の作品名が「A の作品名から前半の表記（1stシーズン・Season1・Part.1・前編・末尾の年）を外したもの＋後半の表記」。後半の表記は 第2クール・2ndシーズン・Season 2・
     セカンドシーズン・第2シーズン・Part.2・第2部・後編・後半。**「第N期」「続編」は入れない**（ゴールデンカムイ 第2期・ダンダダン 第2期は本当の2期）
  - A に後半の表記を付けた作品が2つ以上あれば、シーズンを重ねる番組なのでまとめない（スポンジ・ボブ(シーズン1)〜(シーズン6)）
  - B ごとに当てはまる A が1つだけのとき。続けてまとまるもの（Re:ゼロ 2nd season → 2nd season 第2部）はいちばん前の作品にまとめる
- まとめた作品: Annict の ID・公開キーは前半（annict-1855）。作品名は前半の作品名から前半の表記を外したもの（「Fate/Zero」）。
  話数はまとめた作品の話の数（作品の属性（enrich）は上書きしない）。話は Annict の通し番号なので、後半の話もそのまま同じ作品の話になる。
  AniList の ID・画像は前半のもの

## 期の取り違えを防ぐ規則（ゲート2の追加確認で入れたもの）

- **期は外部DBの区切りのまま別作品として扱う**（同定は前半・後半の作品のまま。分割クールは名寄せの最後に1作品にまとめる。下の「分割クール」）
- **タイトルに期の表記（N期・Season N・2nd シーズン・R2・The Final Season・After/アフターストーリー・完結編。`title_markers`）がある枠は、
  その期を持たない作品に同定しない**。1期の表記なら、2期以降の表記を持つ作品に同定しない。
  対象はアニメのDBの作品（期ごとに別作品）と Wikidata のアニメの記事。実写の Wikidata 作品は全シーズンで1つの項目なので見ない
- タイトルに2期以降の表記があれば、「区間 + 期の表記」で作品名を作り直した候補を先に見る
  （「【ウマ娘プリティーダービー】season２」→「ウマ娘 プリティーダービー Season 2」）。この作品には期をまたぐ通し番号の話数は付けない
- **部の表記（第N部・part N）がタイトルにあれば、部が特定できる作品にだけ同定する**。作品名に同じ部の表記がある、
  または作品名が副題まで含む（同じ照会の候補に、作品名の前方に一致する副題の無い作品がある。ジョジョの各部）ときだけ。
  「ジョジョの奇妙な冒険 第3部」を第1部に付けない。部の表記を単純に外して一致させることはしない
- **英題・ローマ字だけの一致は弱い根拠**。同じ枠のほかの区間が原題で同じ作品に当たっていなければ採用しない
  （Annict は1期の英題がシリーズの総称。「Fate/Zero」「CLANNAD」が常に1期に当たっていた）。
  **和英併記は、英語の区間が日本語の区間で当たった作品の英題と一致すれば同一作品とみなす**
  （「Re:ゼロから始める異世界生活 同時視聴：Re:ZERO -Starting Life in Another World-」）。
  このとき英題の区間は日本語の短い区間の裏付けになり、「短い区間の足切り」を受けない（「日常 同時視聴 / NICHIJOU」）
- **期・部の表記は作品の原題（Annict の作品名・AniList の native・Wikidata の日本語ラベル）だけで見る**。
  Annict の英題・ローマ字は期・部の表記が当てにならない（「スターダストクルセイダース」のローマ字が「… 2nd Season」、「ストーンオーシャン 第3期」が「… Part 3」）
- 同名の作品で保留になっても、同じ枠の英題の区間がどちらか一方に当たっていれば、それを選ぶ（「日常 同時視聴 / NICHIJOU」は同名の映画ではなくアニメ）
- 照会先が違っても MyAnimeList の ID が同じなら同じ作品（Annict の R2 と AniList の R2 を「別々の作品」にしない）
- 期の表記で選んだ作品には話数を紐付けない（区間と期の表記が別の位置にあり、どちらの話数か決められない。期をまたぐ通し番号もある）

## ほかの足切り（ゲート2の追加確認で入れたもの）

- **区間に公開年が書かれていれば、公開年が2年以上違う作品には同定しない**（「GODZILLA(2014)」を1998年版に付けない）
- **タイトルに「総集編・総集篇」があるのに、作品名に総集編の無いテレビ・Web の作品には同定しない**（「チェンソーマン」総集篇 - 前篇 - をテレビ版に付けていた）
- リメイクの足切りは、年のあとに分割の表記が付く作品名（「BASTARD!! -暗黒の破壊神- (2022) part1」）も年付きの同名作品とみなす（2022年の枠が1992年の OVA に当たっていた）
- 「実写見る前に復習」のように「実写」のあとに「前」が続くときは、実写版の手がかりにしない
- 同名の別作品で保留になったときの手がかりに、**枠の時点でまだ公開されていない作品を候補から外す**（「ルックバック」「モアナと伝説の海」の実写版）と、
  **配信の回数（#2 以降・#最終回）があればテレビシリーズ（7話以上）を選ぶ**（映画は1枠で観る。「ひぐらしのなく頃に」#2〜#最終回）を足した
- **ハッシュタグは、記事名の推測（「(映画)」を付けた記事・全文検索）では同定しない**（「#グランツーリスモ」が実写映画に当たっていた）
- 同名の別作品で保留になったとき、タイトルに「アニメ」があればアニメの作品、「実写」があればアニメ以外の作品、区間に年があればその年の作品を選ぶ
- 照合キーの期の番号は、前が数字でないときだけ読む（「機動戦士ガンダム00 2nd season」の「00」を吸い込んで別の期にしない）
- 短い区間の足切りは、短い区間を含む区間（言い換えの元・前後の語を外す前の形）とは比べない（「最終回まで!呪術廻戦 アニメ」で「呪術廻戦」を落とさない）

## Wikidata のラベル（ゲート2の not_found の確認で入れたもの。`wikidata_label`）

- Wikipedia に記事の無い作品（「来る」「笑いのカイブツ」）用。Wikidata の検索（wbsearchentities）で、**日本語ラベルの照合キーが区間と完全一致する作品クラスの項目が1つだけ**なら同定する（`wikidata:label`）。
  **ラベルに日本語（漢字・かな）が無ければ使わない**（日本語のラベルの無い項目は英語のラベルが代わりに返る。「Movie」「cover」「TALK TO ME」が別の作品に当たっていた）。
  区間と同名の Wikipedia の記事が、作品でも原作（小説・漫画など、`source_classes`）でもない一般の語の記事なら、映画の枠のときだけ決める（「【影廊】罰ゲーム同時視聴」が映画「罰ゲーム」に当たっていた）。
  複数なら保留。区間の Wikipedia の記事が曖昧さ回避ページなら保留にし、タイトルに「映画・劇場版」があってラベルの一致が映画1つだけのときだけ選ぶ（「ホラー映画：来る」→ 2018年の映画）。
  **別名（alias）では同定しない**。全文検索と同じく最初の2段だけで使う
- アニメのDBで当たった区間の「同名の別作品」の照合にも、Wikidata のラベル検索を使う（「亜人」の2017年の実写映画は Wikidata にしか無い）

## 視聴系列による期の割り当て（ゲート2の判断1。`src/resolve/series.ts`。`series_assignment`）

- 名寄せの最後に、DB 全体に対して行う（新しい枠で前の枠の期が決まることがあるので毎回全部を見る）
- **視聴系列**: 同じ配信者が、同じ区間（照合キー B）で2枠以上。**系統**: 当たった Annict の作品と同じ Annict シリーズのうち、原題の照合キーが B で始まるテレビ・Web の作品（7話以上。総集編・新編集版は除く）。
  B と原題が一致する作品を1期、ほかは放送順。B と原題が一致する作品が2つ以上（リメイク）の系列は扱わない。
  未同定の枠も、前回この系列で保留にした枠・候補に系統の作品がある枠・タイトルに B（4文字以上）を含む枠を入れる（映画・OVA・総集編の枠と、系統に入らない同じシリーズの作品名を含む枠は入れない）
- 期を決める根拠: 期・部の表記（marker）／「N期」で系統のどの原題にも期・部の表記が無ければ放送順で N 番目（ordinal）／系統の作品の副題を含む（subtitle）／
  枠の時点で放送が始まっていた期が1つだけ（date）／話数の流れ（1話から観始めれば1期・前の枠の続き・前の期の最終話のあと1話に戻れば次の期・作品の話数を超える通し番号。期をまたげば両方の期）／
  **観始め**（系列の最初の枠が「#1」「今日から」「スタート」なら1期。次の枠が「#2」なら番号の無い最初の枠も1期）／
  **続き**（配信の回数 #N が1つ進む、または「最終回」なら前の枠と同じ期。前の枠がその期の最終回なら続けない）／前後の枠が同じ期（前の枠が最終回でない）／
  次の枠で次の期が始まる（1話・今日から・#1）なら前の枠の期／最初の決まった枠が1期の2話以降からなら、その前の枠も1期
- 使わない根拠: **枠数（何枠目か）からの推定**、**「タイトルに続編の表記がない」こと**。期の表記が系統のどの作品にも合わない枠は決めず、その後ろも続きにしない
- 細かい決まり（検証で入れたもの）: 期の表記に合う作品が2つ以上（「season3」に Part.1 と Part.2）なら決めない（「1期」は系統の先頭）。
  「N期」はクールで分かれた作品（「第2クール」「Part 2」「後編」）をひとまとまりに数え、まとまりの中は期の中の話数で選ぶ（「Dr.STONE 第3期 12話～」は NEW WORLD 第2クール）。
  部の表記は、系統の作品名に部の表記があるときだけ見る（ジョジョ第3部の系統は区間がすでに副題）。
  番号の無い最初の枠のすぐ次が途中の話数から（「6話～」）なら、最初の枠も1期（start:gap）。丸数字（「ゆるキャン△②」）は配信の回数。
  総集編・ダイジェスト・総復習の未同定の枠は系列に入れない
- 決まらない枠は、付いていた系統の作品を外して保留（ambiguous。detail の `series` に系列を残す）。1枠だけの系列・期が1つだけの系統には何もしない
- EventWork の match_method は `series:<根拠>`。AI の判定で確定した枠は変えない（根拠としては使う）
- 確認用の一覧: `resolve:series`（data/review/series-assign.md。DB は変えない）

## 作品の属性（2026-10-02 決定。UI の絞り込み用。src/resolve/enrich.ts）

外部DBから自動で埋める（手で分類しない）。名寄せ（resolve）の最後と ai:apply のあとに、まだ埋めていない作品（attrs_at が NULL）だけを埋める。

- `Work.kind` 映像の種類。Annict・AniList の作品はアニメ。Wikidata の作品は次の順で決める

  2. アニメーションのジャンル（`animation_genres`）か anime_classes の分類（P31）があればアニメ
  3. 作品名に `tokusatsu_title_words`（仮面ライダー）があれば特撮（2026-10-02 決定。仮面ライダーギーツは Wikidata にジャンル・シリーズ・フランチャイズが無い）
  4. シリーズ（P179。2段まで）・原作（P144）・フランチャイズ（P8345）のジャンルに特撮があれば特撮（仮面ライダーシリーズ・スーパー戦隊シリーズ・劇場版の原作のテレビシリーズ）。

     原作がキャラクターの項目「ゴジラ」はジャンルが特撮だが受け継がない）
  5. それ以外は実写（実写と CG の合成を含む。ソニック・名探偵ピカチュウ）

  **怪獣映画（ゴジラ・ガメラ）は実写**（2026-10-02 決定。Wikidata のジャンル「怪獣」を特撮に数えない）。シン・ウルトラマンはジャンルが特撮なので特撮。
  **特撮は日本の作品に限る**（`tokusatsu_origin`。原語（P364）が日本語。原語が無ければ制作国に日本。どちらも分からなければ限らない）
- 映画かどうかは `Work.media`（movie）で見る（列を足さない）
- `Work.countries` 制作国（ISO 3166-1 alpha-2 の JSON の並び。順序に意味は持たせない）。Wikidata の P495、無ければ AniList の countryOfOrigin。
  Annict にだけある作品（海外のアニメ映画に多い）は、作品名・「作品名 (映画)」・「作品名 (YYYY年の映画)」の Wikipedia の記事の Wikidata 項目が
  **アニメーションの作品で公開年が±1年**（日本の公開が翌年になる）のときだけ、その P495 を使う（制作国を引くためだけ。同定には使わない）。
  それでも無ければ同じシリーズのほかの作品の制作国がそろっていれば使う。分からなければ NULL（表示は「不明」）

  Annict の作品で series_id が空のもの（視聴系列・AI の判定でシリーズの一覧から作った作品）は Annict の作品のシリーズで埋める（複数なら DB のほかの作品が多く付いているもの）
- Wikidata に日本語のラベルが無い項目（AI の判定で選んだ「We Are Zombies」）は作品名が QID になるので、英語のラベルに直す

## 照会のキャッシュ（resolve_cache。src/resolve/cache.ts。2026-10-11 決定）

- 外部作品DBへの照会結果は、照会先と検索語ごとに resolve_cache に持つ。目的は、ルールを直してやり直すときに同じ照会を繰り返さないこと
- **新しい枠の照会（`resolve`）は30日で取り直す**。外部DBの更新（新しい作品の登録・Wikipedia の記事の新設）を拾うため。
  30日という数字は Phase 2 で置いた既定値で、決定や外部の条件から来たものではない（AniList の規約は保存の期間を定めず、溜め込み・大量収集を禁じている）
- **ルールを直したあとのやり直し（`resolve --all`・`--reason`・`--video`）は、期限切れの結果も使う**。期限で切ると、やり直しのたびに全部を聞き直すことになる
  （約5時間。AniList の照会だけで約17,500回・90回/分）。取り直したいときは `--refresh` を付ける
- **毎回 DB 全体で付け直す型分け（routing）も、期限切れの結果を使う**（新しい枠の区間は、同じ回の名寄せで照会したばかり）
- **Annict のシリーズの一覧・話の一覧（annict_series・annict_series_name・annict_episodes）は、やり直しでも期限どおりに取り直す**。
  新しい期・新しい話が足されるので、古いままだと視聴系列が新しい期を知らずに前の期を割り当てるおそれがある
- 視聴系列・Wikidata のアニメのまとめ・作品の属性・lookup・ai:apply は、期限どおり（30日）
- 見つからなかった結果も覚えるので、やり直しでは新しく登録された作品を拾わない（拾いたいときは `--refresh`）
- lookup の Annict の欄は1語だけで照会する（annict_one）。名寄せの検索（annict）は複数の語をまとめて照会し、返ってきた作品の集まりを語それぞれの結果として覚えるので、
  1語で引くと別の語の作品が混ざる（名寄せは完全一致で選ぶので影響しない）
- 残る課題: 放送中の作品は、覚えている話数が古くなる（最新話の番号を書いた枠が「話数が作品の話数を超えている」で落ちることがある）
